<h3><a id="what-is-linux">What is Linux?</a></h3>
<p>Linux is an open-source, Unix-like operating system. It is widely used for servers, desktops, and mobile devices. It was created by Linus Torvalds in 1991. Unlike proprietary systems like Windows or macOS, Linux allows us to freely modify and distribute its source code. On Windows, the terminal is called CMD, while on Linux, it's referred to as CLI (Command Line Interface).</p>

<h3><a id="why-linux-is-superior">Why Linux is superior to other systems?</a></h3>
<p className="noBottomMargin">Linux is considered superior to other operating systems for several reasons:</p>
<ul>
<li><b>Open-source:</b> Anyone can modify and contribute to its development.</li>
<li><b>Stability:</b> Linux is known for its reliability and uptime, making it ideal for servers and critical applications.</li>
<li><b>Security:</b> Linux has strong built-in security features, making it less susceptible to viruses and malware.</li>
<li><b>Customizability:</b> We can customize nearly every aspect of the system, from the kernel to the user interface.</li>
<li><b>Performance:</b> Linux runs efficiently even on older hardware, providing faster performance compared to many other OSes.</li>
</ul>

<h3><a id="socs">SOCs</a></h3>
<p>One of its advantages is its flexibility, especially when configured for use in a Security Operations Center (SOC). Linux allows administrators to customize the operating system by installing only the necessary packages, making it a lean and efficient platform. By carefully selecting and configuring software tools, administrators can create a system that is perfectly suited to the unique needs of a SOC.</p>

<p className="noBottomMargin"><b>Network packet capture software</b> is an essential tool for SOC analysts, enabling them to capture and thoroughly examine network transactions. Wireshark is one of the most widely used packet capture tools for network analysis. In addition to packet capture tools, other commonly used tools in SOC environments include:</p>

<ul>
  <li><b>Malware analysis tools:</b> Used to safely analyse and observe malware behavior without compromising the underlying system.</li>
  <li><b>Intrusion detection systems (IDS):</b> These monitor network traffic and alert administrators to suspicious activity in real-time.</li>
  <li><b>Firewalls:</b> Used to control traffic flow into and out of a network, protecting it from unauthorized access.</li>
  <li><b>Log managers:</b> Help in managing, collecting, and analyzing large amounts of log data generated by network devices.</li>
  <li><b>Security information and event management (SIEM):</b> Provides real-time analysis and management of security alerts and events.</li>
  <li><b>Ticketing systems:</b> Used for tracking and managing security incidents and task assignments within the SOC.</li>
</ul>

<p>Here are some examples of these tools:</p>

<h5>Sguil</h5>
<p>Sguil is an open-source security console that provides real-time access to intrusion detection system (IDS) alerts. It is often used in combination with other tools in Security Onion, a specialized Linux distribution, to help analysts manage and investigate security events.</p>

<h5>Bro/Zeek</h5>
<p>Zeek (formerly known as Bro) is a powerful network monitoring platform that captures and analyses network traffic. It is commonly used in SOC environments for real-time traffic analysis and alert generation based on traffic patterns.</p>

<h5>Snort</h5>
<p>Snort is a widely used network intrusion detection system (NIDS) that logs network packets and analyses traffic in real-time. It uses signature-based detection to identify potential threats and is commonly deployed in SOCs to detect early signs of intrusion.</p>

<h5>Elastic Stack (ELK)</h5>
<p>The Elastic Stack (consisting of Elasticsearch, Logstash, and Kibana) is a set of tools often used in SOCs for searching, analyzing, and visualizing large volumes of log data. The Elastic Stack helps analysts quickly access and process data, which is crucial for effective incident response.</p>


<h3><a id="nano-and-other-editors">Nano and other editors</a></h3>
<p className="noBottomMargin">In Linux, text editors are essential for editing configuration files, writing scripts, and more. Some popular text editors include:</p>
<ul>
  <li><b>Nano:</b> A simple, user-friendly command-line text editor suitable for beginners.</li>
  <li><b>Vim:</b> A highly configurable, powerful text editor designed for efficient text editing.</li>
  <li><b>Emacs:</b> A powerful, extensible, customizable text editor known for its vast set of features.</li>

<h3><a id="importance-of-configuration-text-files">The importance of configuration text files</a></h3>
<p className="noBottomMargin">Linux stores configuration settings in plain-text files. These files allow us to customize the behavior of the system, services, and applications. Common examples of configuration files include:</p>
<ul>
  <li><b>/etc/fstab:</b> Defines how disk drives and partitions are mounted.</li>
  <li><b>/etc/passwd:</b> Contains user account information.</li>
  <li><b>/etc/ssh/sshd_config:</b> Configuration for the SSH server.</li>
  <li><b>/etc/network/interfaces:</b> Defines network interface configurations.</li>
  <li><b>/etc/hosts:</b> Maps hostnames to IP addresses, allowing for local hostname resolution.</li>
</ul>
<p>Text-based configuration files make Linux flexible, as they can be easily edited, version-controlled, and scripted for automation tasks.</p>

<h3><a id="server-services-and-most-used-ports">Server services and most used ports</a></h3>
<p>A <b>port</b> in computer networking refers to a logical endpoint for communication in a network. It is a 16-bit number (ranging from 0 to 65535) used by the Transport Layer protocols, such as TCP (Transmission Control Protocol) and UDP (User Datagram Protocol), to distinguish different services or applications running on a device. Ports allow multiple applications or services to run on the same machine without interfering with each other by assigning unique numbers for each service.</p>

<p className="noBottomMargin">Here are key points about ports:</p>
<ul>
  <li><b>Well-known ports:</b> Ports 0-1023 are typically reserved for system or widely used services (e.g., HTTP uses port 80, HTTPS uses port 443).</li>
  <li><b>Registered ports:</b> Ports 1024-49151 are used by applications that are not as widely standardized as well-known ports but are still registered for specific services.</li>
  <li><b>Dynamic or private ports:</b> Ports 49152-65535 are used for temporary connections by client applications and are often assigned dynamically by the operating system.</li>
</ul>

<p>Ports play a crucial role in network communication, ensuring that data is routed to the correct service or application on a device. Linux is widely used for hosting server applications. Some of the most common server services and their associated ports include:</p>

<h3><a id="using-a-port-scanner">Using a port scanner</a></h3>
<p>A port scanner is a tool used to check which ports are open on a given server or network device. Commonly used port scanners include:</p>
<ul>
<li><b>Nmap:</b> A powerful and widely used network scanning tool that can detect open ports, services, and vulnerabilities.</li>
<li><b>Netcat:</b> A simple tool for reading and writing data across network connections using TCP (Transmission Control Protocol) or UDP (User Datagram Protocol).</li>
<li><b>Telnet:</b> A simple command-line tool for testing connectivity to remote servers over specific ports.</li>
</ul>
<p>By using a port scanner like Nmap, network administrators can check the security and configuration of their systems, identify open ports, and detect unauthorized services.</p>

<h3><a id="linux-distributions">Linux distributions</a></h3>

<p>Linux distributions refer to the various flavors of Linux operating systems that are packaged with different sets of software, tools, and configurations to meet specific needs. Popular Linux distributions like Ubuntu, CentOS, and Debian are commonly used in SOCs. Security-focused distributions like Kali Linux and Security Onion are tailored for penetration testing and security monitoring. Each distribution has its own package management system, software repositories, and intended use cases, making it essential to choose the right one based on the specific requirements of the SOC or organization. Raspbian is a Debian Linux derivative used in the Raspberry Pi boards.</p>

<h3><a id="virtual-machines">Virtual Machines</a></h3>
<p>Virtual machines (VMs) provide a convenient way to run Linux on a Windows machine without needing to dual-boot or modify the underlying hardware. By using software like VMware or VirtualBox, we can create a virtualized environment to install and run a Linux distribution alongside our existing Windows operating system. This allows developers, administrators, and security analysts to test, configure, or run Linux tools within a controlled and isolated environment. It is an efficient solution for running Linux-specific applications or conducting security analysis, all while keeping the host Windows system intact.</p>

<h3 id="file-permissions">File permissions</h3>

<p class="noBottomMargin">Linux uses file permissions to control who can read, modify, or execute a file. Permissions are assigned separately to the file owner, the group, and other users.</p>

<ul>
  <li><b>file type</b> - indicates the type of filesystem object (```-``` means a regular file, ```d``` means a directory, ```l``` means a symbolic link).</li>
  <li><b>read (r)</b> - allows the contents of a file to be read.</li>
  <li><b>write (w)</b> - allows the contents of a file to be modified.</li>
  <li><b>execute (x)</b> - allows a file to be executed as a program.</li>
  <li><b>owner</b> - the user who owns the file.</li>
  <li><b>group</b> - a group of users that can have permissions assigned to the file.</li>
  <li><b>others</b> - all other users on the system.</li>
</ul>

<p>For example, ```-rwxr-xr--``` means the owner can read, write, and execute the file, the group can read and execute it, and other users can only read it.</p>

<h3><a id="daemons">Daemons</a></h3>
<p className="noBottomMargin"><b>Daemons</b> are background processes that run continuously on a Linux system, often starting automatically during the system boot. They are responsible for handling specific system or application tasks, such as scheduling, logging, or managing services. Common examples of daemons include:</p>
<ul>
  <li><b>cron:</b> Manages scheduled tasks and automates repetitive jobs.</li>
  <li><b>sshd:</b> Handles incoming SSH connections for secure remote access.</li>
  <li><b>httpd:</b> Powers web servers, such as Apache or Nginx.</li>
</ul>
<p>Daemons usually have names ending in <b>d</b>, indicating their function as a service process. They enhance Linux's multitasking capabilities by enabling smooth background operations and service management without user intervention.</p>

<h3><a id="ssh">SSH: Secure Remote Access</a></h3>
<p><b>Secure Shell (SSH)</b> is a protocol that allows us to securely access and manage remote systems over an encrypted connection. SSH is an essential tool for system administrators and SOC analysts, enabling secure communication with servers, transferring files, and executing commands remotely. SSH provides robust authentication methods, including password-based and key-based authentication, ensuring safe access to sensitive systems.</p>
<p>The SSH service on Linux is managed by the <b>sshd</b> daemon, which listens for incoming SSH connections on port 22 by default. Administrators can configure SSH by editing the <b>/etc/ssh/sshd_config</b> file, where options such as allowed authentication methods, permitted IPs, and port numbers can be customized to enhance security.</p>
<p>SSH is not only vital for routine server management but also serves as a secure foundation for tools like secure file transfer (SCP) and remote command execution, making it indispensable in Linux environments.</p>

<h3><a id="device-hardening">Device hardening</a></h3>
<p className="noBottomMargin"><b>Device hardening</b> involves securing a Linux system by minimizing vulnerabilities and configuring it to resist potential attacks. It is a crucial practice for protecting servers, endpoints, and other devices. Key steps in hardening a Linux system include:</p>
<ul>
  <li><b>Disabling unnecessary services:</b> Turn off services and daemons that are not required to minimize the attack surface.</li>
  <li><b>Configuring a firewall:</b> Use tools like <b>iptables</b> or <b>ufw</b> to manage network traffic and block unauthorized access.</li>
  <li><b>Setting strong passwords:</b> Enforce complex password policies and consider multi-factor authentication.</li>
  <li><b>Applying updates:</b> Regularly update the operating system and installed software to patch security vulnerabilities.</li>
  <li><b>File and directory permissions:</b> Restrict access to critical files using proper ownership and permission settings.</li>
  <li><b>Configuring SELinux or AppArmor:</b> Use security modules to enforce strict access controls for applications and services.</li>
  <li><b>Using secure SSH settings:</b> Limit SSH access by disabling root login and using key-based authentication.</li>
  <li><b>Monitoring system logs:</b> Regularly review logs to detect suspicious activity or potential security incidents.</li>
</ul>

<h3><a id="hard-links">Hard links</a></h3>
                                    
<p>A hard link in Linux refers to an inode, which is the data structure that stores metadata and pointers to the actual data blocks of a file. Hard links enable multiple directory entries to refer to the same inode. Essentially, a hard link is another name or alias for an existing file.</p>

<h5>Characteristics of hard links</h5>
<ul>
    <li><b>Indistinguishable from the original file:</b> Hard links and the original file are treated equally by the system. There’s no "original" or "copy" in the case of hard links.</li>
    <li><b>Independent deletion:</b> Deleting one hard link does not affect the others. The file's data is only removed from the disk when the last hard link pointing to the inode is deleted.</li>
    <li><b>Shared inode number:</b> Files created as hard links to each other share the same inode number, as they refer to the same inode and, consequently, the same data blocks on the disk.</li>
    <li><b>File system limitations:</b> Hard links cannot span across different file systems because the inode reference is unique to each file system.</li>
    <li><b>Directory restrictions:</b> Hard links cannot be created for directories (except for ```.``` and ```..```, which are system-generated hard links).</li>
</ul>
<p>Hard links provide an efficient way to create multiple references to the same file without duplicating the file's content, which saves disk space.</p>

<h3><a id="processes">Processes</a></h3>
<p>In Linux, processes are instances of running programs. Each process is assigned a unique Process ID (PID) and is managed by the kernel. When a program is executed, a new process is created, often through a mechanism called <b>forking</b>, where the current process creates a copy of itself.</p>

<p>Several commands help manage and monitor processes in Linux:</p>

<div className="table-container"><table>
    <tr>
        <td>```ps```</td>
        <td>Displaying a snapshot of the currently running processes, including the PID, terminal, and resource usage. It's commonly used with options like ```-aux``` to see all running processes.</td>
    </tr>
    <tr>
        <td>```top```</td>
        <td>Showing real-time information about system processes, including CPU and memory usage. It’s often used to monitor resource-hogging processes.</td>
    </tr>
    <tr>
        <td>```kill```</td>
        <td>Terminating processes by sending signals. The most common signal is ```SIGKILL``` (usually sent with PID) to forcefully stop a process.</td>
    </tr>
    <tr>
        <td>```killall```</td>
        <td>Terminating all processes with a specific name. For example, ```killall firefox``` would stop all Firefox processes.</td>
    </tr>
    <tr>
        <td>```htop```</td>
        <td>An interactive process viewer, similar to ```top```, but with a more user-friendly interface and additional features like sorting by resource usage.</td>
    </tr>
    <tr>
        <td>```nohup```</td>
        <td>Running a command in the background, even after the user has logged out. It prevents the process from being terminated when the session ends.</td>
    </tr>
    <tr>
        <td>```| (pipe)```</td>
        <td>The pipe operator allows you to send the output of one command as the input to another. For example, ```ps aux | grep firefox``` will filter the list of processes to show only those related to Firefox.</td>
    </tr>
</table></div>

<h3><a id="forks">Forks</a></h3>

<p><b>Forking</b> is a key concept in Linux, where a running process creates a new process by duplicating itself. The new process is called the child process, and it gets its own unique Process ID (<b>PID</b>). This is typically used in multitasking systems, where the operating system enables the concurrent execution of multiple processes. Forking allows a parent process to create child processes, which can run independently or cooperate with the parent.</p>
