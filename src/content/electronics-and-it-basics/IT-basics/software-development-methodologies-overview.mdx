<p>Software development methodologies are structured approaches to planning, executing, and managing software projects. They provide frameworks for teams to follow, ensuring that projects are completed efficiently and effectively.</p>

<h2>Agile</h2>

<p>Agile is a flexible and iterative software development methodology focused on delivering value to the customer quickly and adapting to changing requirements. Instead of building the entire product before release, Agile promotes working in small, incremental steps known as iterations or <b>sprints</b> (typically 1-4 weeks). Agile encourages <b>regular feedback</b>, collaboration between cross-functional teams, and continuous improvement.</p>
<p className="noBottomMargin"><b>Key principles of Agile include:</b></p>
<ul>
    <li>Customer collaboration over contract negotiation.</li>
    <li>Responding to change over following a plan.</li>
    <li>Working software over comprehensive documentation.</li>
    <li>Individuals and interactions over processes and tools.</li>
</ul>
<p><b>Example:</b> A startup building a mobile app releases a new version every two weeks, each adding small features based on user feedback.</p>

<h2>Scrum</h2>

<p>Scrum is a specific framework within Agile. It structures work into fixed-length iterations called <b>sprints</b>, typically lasting 2-4 weeks. During each sprint, a self-organizing team works on a defined set of tasks from a <b>backlog</b> (a list of the features for the software in a prioritized list), aiming to deliver a potentially shippable product increment. When a feature gets close to the top of the priority list, it gets broken down into smaller tasks called user <b>stories</b>. A story should be small enough that a single team can finish it within a single sprint. Every day, each scrum team should have a daily stand-up. A <b>stand-up</b> is a meeting that should last no longer than 15 minutes and should take place at the same time every day. Scrum includes defined roles and ceremonies.</p>
<p className="noBottomMargin"><b>Key components of Scrum:</b></p>
<ul>
    <li><b>Roles:</b> Product Owner, Scrum Master, Development Team.</li>
    <li><b>Events:</b> Sprint Planning, Daily Stand-up, Sprint Review, Sprint Retrospective.</li>
    <li><b>Artifacts:</b> Product Backlog, Sprint Backlog, Increment.</li>
</ul>
<p><b>Example:</b> A software team holds daily stand-ups and delivers a tested login system at the end of a 2-week sprint.</p>

<h2>Kanban</h2>

<p>Kanban is another Agile-based methodology focused on visualizing work and optimizing flow. It uses a Kanban board divided into columns (e.g., To Do, In Progress, Done) to represent work stages. Each task is a card that moves across the board. Kanban limits the number of tasks in progress (WIP) to avoid overload and ensure steady delivery.</p>
<p className="noBottomMargin"><b>Benefits of Kanban:</b></p>
<ul>
    <li>Flexibility - no fixed iterations.</li>
    <li>Better visibility of work status.</li>
    <li>Focus on continuous delivery.</li>
</ul>
<p><b>Example:</b> A customer support team uses a Kanban board to manage incoming tickets, ensuring no more than three are handled simultaneously.</p>

<h2>Lean</h2>

<p>Lean is a methodology that originated in manufacturing (Toyota Production System) and later adapted to software development. It focuses on maximizing value by eliminating waste (any activity not adding value to the customer). Lean emphasizes efficiency, fast delivery, and continuous learning.</p>
<p className="noBottomMargin"><b>Key Lean principles:</b></p>
<ul>
    <li><b>Eliminate waste</b> - remove any activity that does not add value to the customer.</li>
    <li><b>Amplify learning</b> - encourage feedback and continuous improvement through small, frequent releases.</li>
    <li><b>Decide as late as possible</b> - delay decisions until they are based on facts, not assumptions.</li>
    <li><b>Deliver as fast as possible</b> - shorten delivery cycles to get feedback and value sooner.</li>
    <li><b>Empower the team</b> - give teams autonomy and trust to make decisions.</li>
    <li><b>Build integrity in</b> - ensure quality is part of the process, not something added later.</li>
    <li><b>Optimize the whole</b> - improve the entire system, not just individual parts.</li>
</ul>                                      
<p><b>Example:</b> A development team avoids over-documenting and focuses only on building features that solve real customer problems.</p>

<h2>Waterfall</h2>

<p>Waterfall is a traditional, linear software development methodology in which each phase is completed before moving on to the next. These phases are collectively known as the Software Development Life Cycle (SDLC), which outlines the stages involved in developing software applications. Waterfall is best suited for projects with <b>well-defined requirements</b> and minimal expected changes. You can imagine each stage as a single cascade in a waterfall - <b>flowing sequentially and without turning back</b>. Once a phase is completed, the process moves forward, and revisiting previous stages is typically not allowed.</p>

<p><b>Example:</b> A government agency commissions a software system with fixed requirements, using Waterfall to deliver the final product after 12 months of planned work.</p>

                                    <h2>Different software development approaches</h2>

<h5>Test-Driven Development (TDD)</h5>
<p>Test-Driven Development is a software development approach in which <b>tests are written before the actual code</b>. Developers first define the desired functionality through tests, then write code to pass those tests. TDD ensures that the software is <b>robust, maintainable, and less prone to bugs</b>, because all features are verified continuously. It promotes simple design and encourages developers to think carefully about requirements before implementation.</p>

<h5>Extreme Programming (XP)</h5>
<p>Extreme Programming is an <b>agile software development methodology</b> that emphasizes frequent releases, continuous feedback, and close collaboration between developers and customers. XP focuses on <b>best practices such as pair programming, test-driven development, and simple design</b> to improve code quality and adaptability to changing requirements. The approach encourages short development cycles and constant communication to ensure that the software meets the user’s needs effectively.</p>

<h5>Intelligent Programming</h5>
<p>Intelligent Programming is an approach that incorporates <b>automation, AI, and advanced tools</b> to assist developers in writing, testing, and maintaining code. This approach focuses on <b>improving developer productivity</b> by leveraging intelligent code suggestions, automatic error detection, and adaptive algorithms that can optimize code structure or detect potential bugs before execution. It’s often combined with other development methodologies to make the development process more efficient.</p>

<h5>Feature-Driven Development (FDD)</h5>
<p>Feature-Driven Development is an iterative and <b>model-driven agile process</b> that organizes development around features. A “feature” is a small, client-valued function, and FDD emphasizes <b>planning, designing, and building features incrementally</b>. This approach improves project visibility, ensures steady progress, and keeps the team focused on delivering tangible results regularly.</p>
