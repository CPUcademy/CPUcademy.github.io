<p>Creational patterns deal with the construction of objects. An object can be created wholesale (in a single statement) or piecewise (step by step).</p>

<h2><a id="builder">Builder</a></h2>

<p>When an object takes long to initialize, provide an API for constructing it succinctly. Separate the construction of a complex object from its representation, allowing the same construction process to create various representations. A Builder is a separate component for building an object.</p>

```python
class Pizza:
    def __init__(self):
        self.pizza_size = None
        self.cheese = None
        self.pepperoni = False
        self.mushrooms = False
        self.extra_toppings = []

    def __str__(self):
        return f"Pizza(Size: {self.pizza_size}, Cheese: {self.cheese}, Pepperoni: {self.pepperoni}, Mushrooms: {self.mushrooms}, Extra Toppings: {self.extra_toppings})"

class PizzaBuilder:
    def __init__(self):
        self.pizza = Pizza()

    def set_size(self, pizza_size):
        self.pizza.pizza_size = pizza_size
        return self # returning the class object itself to perform chaining (see the explanation below)

    def add_cheese(self, cheese_type):
        self.pizza.cheese = cheese_type
        return self

    def add_pepperoni(self):
        self.pizza.pepperoni = True
        return self

    def add_mushrooms(self):
        self.pizza.mushrooms = True
        return self

    def add_topping(self, topping):
        self.pizza.extra_toppings.append(topping)
        return self

    def build(self):
        return self.pizza

custom_pizza = PizzaBuilder().set_size("Large").add_cheese("Cheddar").add_pepperoni().add_topping("Olives").build()
print(custom_pizza)

veggie_pizza = PizzaBuilder().set_size("Medium").add_cheese("Mozzarella").add_mushrooms().add_topping("Bell Peppers").add_topping("Onions").build()
print(veggie_pizza)
```

<h5>Chaining</h5>

<p>Because of method chaining, multiple methods can be executed sequentially in a single statement. This is possible because each method returns the class object, allowing the next method to be called immediately.</p>

```python
class Box:
    def __init__(self, box_length, box_width):
        self.box_length = box_length
        self.box_width = box_width

    def set_dimensions(self, box_length, box_width):
        self.box_length = box_length
        self.box_width = box_width
        return self # returning the class object itself

box = Box(5, 10)
box.set_dimensions(7, 14).box_length = 8
print(box.box_length, box.box_width)
```

<h4>Builder inheritance</h4>

<p>When the built classes form a hierarchy (e.g., ```Employee``` inherits from ```Person```), their Builders can form a parallel hierarchy, so a subclass Builder inherits the parent Builder's methods instead of repeating them. In Python, an inherited method that returns ```self``` returns the subclass Builder, so chaining works without any extra code (we can call ```job()``` after ```called()```).</p>

```python
class Person:
    def __init__(self, builder):
        self.name = builder.name

    def __str__(self):
        return self.name

class PersonBuilder:
    def __init__(self):
        self.name = None

    def called(self, name):
        self.name = name
        return self # returning the subclass Builder, so chaining continues with its methods

    def build(self):
        return Person(self)

class Employee(Person):
    def __init__(self, builder):
        super().__init__(builder)
        self.job_title = builder.job_title
        self.salary = builder.salary

    def __str__(self):
        return f"{super().__str__()} works as {self.job_title}, earns {self.salary}"

class EmployeeBuilder(PersonBuilder):
    def __init__(self):
        super().__init__()
        self.job_title = None
        self.salary = None

    def job(self, job_title):
        self.job_title = job_title
        return self

    def earns(self, salary):
        self.salary = salary
        return self

    def build(self):
        return Employee(self)

employee = EmployeeBuilder().called("Josh").job("Engineer").earns(100000).build()
print(employee)
```

<h2><a id="factories">Factories</a></h2>

<h3>Static Factory Method</h3>

<p>A static factory method is an alternate constructor: a method that returns an instance of its class. It provides an additional way to create objects, often with a more descriptive name or specialized logic (e.g., validation or conversion), while keeping the main ```__init__()``` constructor simple. For example, instead of the user's age, we can take his date of birth and then calculate the age. In Python, they are usually created with the ```@classmethod``` decorator (like shown <a href="/tutorials/python/python-decorators#class-methods" className="link">here</a>), which receives the class as ```cls```, so the method also works for subclasses. A class can have multiple static factory methods. Despite the similar name, this is not the Factory Method design pattern (described below).</p>

```python
from datetime import date

class Person:
    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def __str__(self):
        return f"{self.__name}, {self.__age}"

    @classmethod
    def from_age(cls, name, age):
        return cls(name, age)

    @classmethod
    def from_birth_year(cls, name, birth_year):
        return cls(name, date.today().year - birth_year)

person1 = Person.from_age("Josh", 25)
person2 = Person.from_birth_year("John", 1980)

print(person1)
print(person2)
```

<p>Static factory methods can live in the class they create, which is the common choice when the creation logic is closely related to the class (e.g., ```dict.fromkeys()``` or ```datetime.fromtimestamp()```). If the creation logic becomes complex or needs its own dependencies, it can be moved into a separate Factory class.</p>

```python
from datetime import date

class PersonFactory:
    @staticmethod
    def from_age(name, age):
        return Person(name, age)

    @staticmethod
    def from_birth_year(name, birth_year):
        return Person(name, date.today().year - birth_year)

class Person:
    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def __str__(self):
        return f"{self.__name}, {self.__age}"

person1 = PersonFactory.from_age("Josh", 25)
person2 = PersonFactory.from_birth_year("John", 1980)

print(person1)
print(person2)
```

<h3>Factory Method</h3>

<p>The Factory Method pattern defines a method in a base class for creating objects, while allowing subclasses to determine which concrete class to instantiate. The base class works with the created object through its interface, so it does not need to know its specific implementation.</p>

```python
from abc import ABC, abstractmethod

class Vehicle(ABC):
    @abstractmethod
    def drive(self):
        pass

class Car(Vehicle):
    def drive(self):
        return "Driving a car"

class Bike(Vehicle):
    def drive(self):
        return "Riding a bike"

class Rental(ABC):
    @abstractmethod
    def create_vehicle(self): # the Factory Method
        pass

    def rent(self):
        vehicle = self.create_vehicle()
        return f"Your rental is ready. {vehicle.drive()}"

class CarRental(Rental):
    def create_vehicle(self):
        return Car()

class BikeRental(Rental):
    def create_vehicle(self):
        return Bike()

print(CarRental().rent())
print(BikeRental().rent())
```

<h3>Abstract Factory</h3>

<p>An Abstract Factory is an interface for creating families of related objects without specifying their concrete classes. Each concrete Factory produces a set of products designed to work together, so the client can't accidentally mix, e.g., a Windows button with a Mac checkbox.</p>

```python
from abc import ABC, abstractmethod

class Button(ABC):
    @abstractmethod
    def render(self):
        pass

class Checkbox(ABC):
    @abstractmethod
    def render(self):
        pass

class WindowsButton(Button):
    def render(self):
        return "Windows button"

class WindowsCheckbox(Checkbox):
    def render(self):
        return "Windows checkbox"

class MacButton(Button):
    def render(self):
        return "Mac button"

class MacCheckbox(Checkbox):
    def render(self):
        return "Mac checkbox"

class GUIFactory(ABC): # an Abstract Factory
    @abstractmethod
    def create_button(self):
        pass

    @abstractmethod
    def create_checkbox(self):
        pass

class WindowsFactory(GUIFactory): # a concrete Factory
    def create_button(self):
        return WindowsButton()

    def create_checkbox(self):
        return WindowsCheckbox()

class MacFactory(GUIFactory):
    def create_button(self):
        return MacButton()

    def create_checkbox(self):
        return MacCheckbox()

def render_form(factory: GUIFactory):
    button = factory.create_button()
    checkbox = factory.create_checkbox()
    print(f"{button.render()} and {checkbox.render()}")

render_form(WindowsFactory())
render_form(MacFactory())
```

<h2><a id="prototype">Prototype</a></h2>

<p>Prototype allows object cloning instead of creating new instances from scratch, improving efficiency and flexibility. Sometimes it is more efficient to clone an object and modify it, instead of initializing a new one. A Prototype is a partially or fully initialized object that we can copy (clone) and modify. A Prototype often contains other objects, so the copy must be deep (```copy.deepcopy()``` copies the nested objects too). Otherwise, the clone would share them with the original, and modifying one would modify the other.</p>

```python
import copy

class Address:
    def __init__(self, street, suite):
        self.street = street
        self.suite = suite

    def __str__(self):
        return f"{self.street}, Suite {self.suite}"

class Employee:
    def __init__(self, name, address):
        self.name = name
        self.address = address

    def clone(self):
        return copy.deepcopy(self) # creating a deep copy (the Address is copied instead of shared)

    def __str__(self):
        return f"{self.name} works at {self.address}"

john = Employee("John", Address("123 East Dr", 100)) # creating an original object

jane = john.clone() # cloning the object
jane.name = "Jane" # modifying the cloned object
jane.address.suite = 200

print(john) # John's suite hasn't changed because the Address was copied too
print(jane)
```

<h4>Prototype Factory</h4>

<p>Factories can provide a convenient API for using Prototypes. The Factory stores preconfigured Prototypes (e.g., employees of different offices) and clones them, so the client only provides the details that differ.</p>

```python
import copy

class Address:
    def __init__(self, street, suite):
        self.street = street
        self.suite = suite

    def __str__(self):
        return f"{self.street}, Suite {self.suite}"

class Employee:
    def __init__(self, name, address):
        self.name = name
        self.address = address

    def clone(self):
        return copy.deepcopy(self)

    def __str__(self):
        return f"{self.name} works at {self.address}"

class EmployeeFactory:
    # Preconfigured Prototypes
    main_office_employee = Employee("", Address("123 East Dr", 0))
    aux_office_employee = Employee("", Address("123B East Dr", 0))

    @staticmethod
    def _new_employee(prototype, name, suite):
        employee = prototype.clone() # cloning the Prototype
        employee.name = name # customizing the clone
        employee.address.suite = suite
        return employee

    @staticmethod
    def new_main_office_employee(name, suite):
        return EmployeeFactory._new_employee(EmployeeFactory.main_office_employee, name, suite)

    @staticmethod
    def new_aux_office_employee(name, suite):
        return EmployeeFactory._new_employee(EmployeeFactory.aux_office_employee, name, suite)

john = EmployeeFactory.new_main_office_employee("John", 101)
jane = EmployeeFactory.new_aux_office_employee("Jane", 500)

print(john)
print(jane)
```

<h2><a id="singleton">Singleton</a></h2>

<p>Singleton ensures a class has only one instance and provides a global point of access to it. Sometimes, it doesn't make sense to have more than one object in the system, e.g., a database or an object Factory, because the initializer is expensive or is just unnecessary. A Singleton is a component that is instantiated only once (we want to prevent anyone from creating additional copies).</p>

```python
class Database:
    _instance = None # a class-level attribute to store the single instance

    def __new__(cls, *args, **kwargs):
        if cls._instance is None: # checking if an instance already exists
            cls._instance = super().__new__(cls) # creating and storing the single instance
        return cls._instance

    def get_data(self):
        print("Loading data")

s1 = Database()
s2 = Database()
s1.get_data()
s2.get_data()

print(s1 is s2) # these two instances are really the same instance
```

<p>The class in the example above can only have one instance, but if we add an ```__init__()``` method to it, it will execute two times. This can be fixed with a decorator or a metaclass (they can be used to enforce a true Singleton).</p>

```python
def singleton(cls):
    instances = {}

    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs) # creating and storing the instance
        return instances[cls] # returning the existing instance

    return get_instance # returning the wrapper function

@singleton
class Database:
    def __init__(self):
        print("Loading database")

s1 = Database()
s2 = Database()
print(s1 is s2)
```

```python
class SingletonMeta(type):
    _instances = {}
    
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs) # creating and storing the instance
        return cls._instances[cls] # returning the existing instance

class Database(metaclass = SingletonMeta):
    def __init__(self):
        print("Loading database")

s1 = Database()
s2 = Database()
print(s1 is s2)
```

<p>Singletons ensure a single instance of a class, which is useful for managing shared resources like database connections or logging systems, preventing redundant object creation. However, they can introduce hidden dependencies and make unit testing difficult due to the global state, leading to unexpected side effects (such as unintended data modifications, stale state across tests, and difficulties in resetting the state for different parts of an application). Additionally, they violate the Single Responsibility Principle (SRP) by controlling both their lifecycle and primary functionality, making the code harder to maintain and extend.</p>

<h2><a id="monostate">Monostate (Singleton variation)</a></h2>

<p>Monostate allows multiple instances of a class to share the same state by making all instances point to a common dictionary (```__dict__```). Unlike the Singleton pattern (which ensures only one instance exists), Monostate allows multiple instances but guarantees they behave as if they are the same object in terms of state. The client doesn't have to know that the state is shared.</p>

```python
class Monostate:
    _state = {}

    def __new__(cls, *args, **kwargs):
        instance = super().__new__(cls)
        instance.__dict__ = cls._state # all instances share the same attributes
        return instance

a = Monostate()
b = Monostate()

a.value = "Value A"
b.value = "Value B"

print(a.value)
print(b.value)
```

<h2><a id="lazy-initialization">Lazy Initialization</a></h2>

<p>Lazy Initialization delays the creation of an object or a resource until it is actually needed, rather than when the object is first created. This is useful for optimizing resource usage, especially when the initialization of an object is resource-intensive or unnecessary if the object is never used. The example below adheres to this design pattern because it ensures that the database connection and any associated resources are only initialized when the ```get_data()``` method is first called, i.e., when the data is needed for the first time.</p>

```python
class LazyDatabase:
    def __init__(self):
        self._db_connection = None

    def _initialize(self):
        print("Initializing database connection...")
        self._db_connection = "Database connection established"

    def get_data(self):
        if self._db_connection is None:
            self._initialize() # initializing only when data is requested
        print("Fetching data from database")

db = LazyDatabase()
db.get_data() # the database is initialized only when we call get_data()
db.get_data() # accessing the data again, no re-initialization occurs
```

<h2><a id="dependency-injection">Dependency Injection</a></h2>

<p>Dependency Injection allows us to inject dependencies (such as services, objects, or configurations) into a class rather than having the class create them itself. This promotes loose coupling (meaning the class has less direct knowledge or control over the specific implementation details of its dependencies), making the code more modular, flexible, and easier to test. With DI, the class doesn't need to worry about how its dependencies are created or managed. Instead, they are provided externally (often by a framework or a container), which simplifies testing and maintenance.</p>

```python
from abc import ABC, abstractmethod

class Database(ABC):
    @abstractmethod
    def connect_db(self):
        pass

class MySQLDatabase(Database):
    def connect_db(self):
        print("Connecting to MySQL database...") # MySQL implementation

class SQLiteDatabase(Database):
    def connect_db(self):
        print("Connecting to SQLite database...") # SQLite implementation

class DataService:
    def __init__(self, db: Database):
        self.db = db # injecting the dependency through the constructor

    def execute_action(self):
        print("Service is running...")
        self.db.connect_db() # using the injected dependency

# Creating database instances
mysql_db = MySQLDatabase()
sqlite_db = SQLiteDatabase()

# Injecting the Database instances into the DataService
service1 = DataService(mysql_db) # using MySQL
service1.execute_action()
service2 = DataService(sqlite_db) # using SQLite
service2.execute_action()
```
