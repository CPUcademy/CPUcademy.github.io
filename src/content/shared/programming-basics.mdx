<h2>Low-level VS high-level programming languages</h2>
<p className="noBottomMargin">Programming languages can be categorized into low-level and high-level languages based on their abstraction from machine instructions:</p>
<ul>
  <li><b>Low-level languages:</b> These are closer to the hardware and include Assembly. They offer high performance and control over system resources but require more effort to write and debug. They rely directly on the processor's instruction set for execution.</li>
  <li><b>High-level languages:</b> These are closer to human language and include Python and Java. They are easier to write, read, and maintain but are less efficient compared to low-level languages as they rely on interpreters or compilers to convert code into machine instructions.</li>
</ul>

<h2>Compiled VS interpreted languages</h2>
<p className="noBottomMargin">Programming languages can be classified based on how their code is executed:</p>
<ul>
  <li><b>Compiled languages:</b> These languages, like C++ and Java, require a compiler to convert the source code into machine code before execution. The compilation process improves performance but adds an additional step.</li>
  <li><b>Interpreted languages:</b> These languages, like Python and JavaScript, are executed line-by-line by an interpreter. They are easier to debug and run but can be slower than compiled languages.</li>
</ul>

<h2>Statically typed VS dynamically typed languages</h2>
<p className="noBottomMargin">Programming languages can also be categorized based on how they handle variable types:</p>
<ul>
  <li><b>Statically typed languages:</b> These languages, like Java and C++, require variable types to be explicitly declared at compile time. Type checking is performed before execution, reducing runtime errors but requiring more upfront definition.</li>
  <li><b>Dynamically typed languages:</b> These languages, like Python and JavaScript, determine variable types at runtime. They offer more flexibility and reduce the need for explicit type declarations but may lead to unexpected errors during execution.</li>
</ul>

<h2>Programming paradigms</h2>
<p>Programming paradigms are fundamental approaches to designing and writing programs.</p>

<h4>Imperative programming</h4>
<p className="noBottomMargin">Imperative programming describes <b>how</b> a program should perform a task through a sequence of commands that modify program state.</p>
<ul>
  <li><b>Procedural programming:</b> Organizes code into procedures (functions).</li>
  <li><b>Object-oriented programming (OOP):</b> Organizes programs as interacting objects that encapsulate data and behavior.</li>
</ul>

<h4>Declarative programming</h4>
<p className="noBottomMargin">Declarative programming describes <b>what</b> result should be achieved without specifying the exact steps.</p>
<ul>
  <li><b>Functional programming:</b> Treats computation as the evaluation of mathematical functions while avoiding mutable state and side effects.</li>
  <li><b>Logic programming:</b> Solves problems by defining facts and rules, allowing the system to infer solutions automatically.</li>
</ul>

<h2>Programming styles</h2>
<p className="noBottomMargin">Programming styles describe how programs are organized or executed. They can be combined with different programming paradigms.</p>
<ul>
  <li><b>Event-driven programming:</b> Program execution is driven by events such as user actions, sensor input, or messages.</li>
  <li><b>Concurrent programming:</b> Multiple tasks make progress during overlapping periods of time.</li>
  <li><b>Parallel programming:</b> Multiple computations execute simultaneously on multiple processors or CPU cores.</li>
  <li><b>Reactive programming:</b> Programs respond to asynchronous data streams and automatically propagate changes.</li>
</ul>

<h2>Alphabet VS syntax VS semantics VS lexis</h2>
<p className="noBottomMargin">These concepts are fundamental to understanding how programming languages are structured:</p>
<ul>
  <li><b>Alphabet:</b> The set of valid characters or symbols in a language, such as letters, digits, and operators.</li>
  <li><b>Syntax:</b> The rules that define the correct structure and format of statements in a language.</li>
  <li><b>Semantics:</b> The meaning behind syntactically correct statements or expressions.</li>
  <li><b>Lexis:</b> The vocabulary of a language, including keywords and identifiers.</li>
</ul>

<h2>How to write names?</h2>
<p className="noBottomMargin">The following naming conventions are commonly used to improve readability and maintain consistency in programming:</p>
<ul>
  <li><b>Camel case:</b> Words are written without spaces, and each word after the first starts with an uppercase letter. Example: ```camelCaseExample```.</li>
  <li><b>Pascal case:</b> Similar to camel case, but the first word also starts with an uppercase letter. Example: ```PascalCaseExample```.</li>
  <li><b>Snake case:</b> Words are separated by underscores, with all letters typically in lowercase. Example: ```snake_case_example```.</li>
  <li><b>Kebab case:</b> Words are separated by hyphens, often used in URLs or CSS class names. Example: ```kebab-case-example```.</li>
</ul>

<h2>Programs VS processes</h2>
<p>A <b>program</b> is a set of instructions written to perform a specific task, while a <b>process</b> is the execution of a program by the operating system, including its current state and resources. There can be multiple processes running from the same program simultaneously.</p>

<h2>Absolute VS relative file paths</h2>
<p className="noBottomMargin">When working with files in programming, paths can be specified in two ways:</p>
<ul>
  <li><b>Absolute path:</b> This specifies the full path from the root directory to the target file. For example, ```C:\Users\John\Documents\file.txt``` (Windows) or ```/home/john/documents/file.txt``` (Linux).</li>
  <li><b>Relative path:</b> This specifies the path relative to the current working directory. For example, ```/data/document.txt``` refers to a file located in a folder named ```files``` within the current directory.</li>
</ul>

<h2>Time</h2>

<p>In Unix systems, a timestamp represents the number of seconds that have passed since January 1, 1970, 00:00:00 (UTC). This starting point, known as the Unix epoch, marks the beginning of time measurement for Unix-based systems. The Unix epoch was selected as a practical and arbitrary reference. By using a continuous count of seconds, it streamlines time calculations and eliminates the challenges posed by calendar irregularities, such as leap years or months with varying numbers of days.</p>

<h2>Important file extensions</h2>

<p>In software development and configuration, certain file formats are widely used for storing and exchanging structured data. Three of the most common are ```.json```, ```.xml```, and ```.yaml```. Each has its own syntax and preferred use cases, often depending on readability, complexity, or tool compatibility.</p>

<p><b>JSON (.json)</b> - JavaScript Object Notation is a lightweight format used to represent structured data, especially in web APIs and configurations.</p>

```json
{
  "name": "John",
  "age": 30,
  "active": true
}
```

<p><b>XML (.xml)</b> - Extensible Markup Language is a verbose but flexible format often used in document storage, data exchange between systems, and Android development.</p>

```json
<user>
  <name>John</name>
  <age>30</age>
  <active>true</active>
</user>
```

<p><b>YAML (.yaml / .yml)</b> - YAML Ain’t Markup Language is a human-readable format used primarily in configuration files, especially in tools like Docker, Kubernetes, and CI/CD systems.</p>

```json
name: John
age: 30
active: true
```

<h2>Complexity</h2>

<p><b>Time complexity</b> measures how the execution time of an algorithm changes with the size of the input. It helps estimate how fast an algorithm runs, usually expressed using Big O notation, such as O(1), O(n), O(log n), or O(n<sup>2</sup>). It is crucial for optimizing performance, especially with large datasets.</p>

<img src="/data/courses/big_o_plot.png" alt="Window" id="bigo" className="img-fluid"/>

<p><b>Space complexity</b> measures how much memory an algorithm uses relative to the input size. It includes memory for variables, data structures, and function call stacks. Analyzing space complexity helps ensure that programs run efficiently without exhausting system memory.</p>

<h2>Important terms</h2>

<ul>
  <li><b>Refactorization</b> - the process of restructuring existing code without changing its external behavior to improve readability and reduce complexity.</li>
  <li><b>Lorem ipsum</b> - a text consisting of Latin and quasi-Latin words, with roots in classical Latin, modeled on a fragment of Cicero's treatise "On the Limits of Good and Evil." The text is used to demonstrate typefaces (fonts). It was first used by an unknown printer in the 16th century.</li>
  <li><b>API</b> - Application Programming Interface, a set of rules and protocols that allows different software applications to communicate with each other. It defines the methods and data formats that programs can use to request and exchange information.</li>
  <li><b>API key</b> - a unique identifier used to authenticate and authorize access to an API, ensuring that only authorized users or systems can interact with it.</li>
  <li><b>API gateway</b> - a server that acts as an intermediary between clients and backend services, managing API requests, authentication, rate limiting, and routing to ensure secure and efficient communication between systems.</li>
  <li><b>API middleware</b> - software that sits between an application and an API, processing API requests and responses before they reach their destination while also handling tasks such as authentication, logging, validation, caching, and data transformation.</li>
  <li><b>URI</b> - Uniform Resource Identifier, a general term used to identify a resource. A URI can locate a resource (URL), name it (URN), or do both.</li>
  <li><b>URL</b> - Uniform Resource Locator, a specific type of URI that provides the address used to locate a resource on the Internet. It includes the protocol (HTTP, HTTPS), domain, and path.</li>
  <li><b>URN</b> - Uniform Resource Name, a type of URI that names a resource uniquely without necessarily providing its location. For example, "urn:isbn:0451450523" uniquely identifies a book by its ISBN.</li>
  <li><b>Framework</b> - a pre-built structure of code and tools that provides a foundation for developing software applications efficiently and consistently.</li>
  <li><b>ASCII table</b> - a standardized character encoding system that assigns numeric values to letters, digits, punctuation marks, and control characters, allowing computers to represent text.</li>
  <li><b>Source code</b> - the human-readable instructions written by programmers to create software, which can be open source (freely accessible and modifiable) or closed source (restricted and proprietary).</li>
  <li><b>CRUD</b> - Create, Read, Update, Delete; the four basic operations that are the foundation for managing data in a database or an application.</li>
  <li><b>SaaS</b> - Software as a Service, a cloud-based service where applications are hosted and maintained by a service provider, and users access the software over the internet, typically via a subscription model.</li>
  <li><b>CRM</b> - Customer Relationship Management, a strategy and software system used by organizations to manage interactions with current and potential customers, track data, and improve customer relationships.</li>
  <li><b>EOF (End-Of-Line)</b> - a character or sequence of characters that marks the end of a line of text.</li>
  <li><b>A command</b> - an instruction given to a computer program to perform a specific task or operation.</li>
  <li><b>Bytecode</b> - an intermediate representation of source code that is typically generated after compiling a high-level programming language. Bytecode is platform-independent, allowing it to be executed on different systems by a virtual machine or runtime environment.</li>
  <li><b>Machine code</b> - the lowest-level representation of a program, consisting of binary instructions that a computer's processor can directly execute. Machine code is specific to the architecture of the processor and is the result of compiling or assembling high-level code into a form that the hardware understands.</li>
  <li><b>IDE</b> - Integrated Development Environment, a software application that provides comprehensive tools and features for software development.</li>
  <li><b>Overflow</b> - a condition that occurs when a calculation or data operation exceeds the maximum limit of storage capacity for a variable, memory space, or buffer. For example, adding 1 to the maximum value of a 32-bit signed integer (2,147,483,647) causes it to wrap around to -2,147,483,648.</li>
  <li><b>Heap size</b> - the amount of memory allocated to the heap, where dynamic memory allocation occurs during program execution. Exceeding this limit can lead to an ```OutOfMemoryError``` or program crashes.</li>
  <li><b>Line ending (EOL)</b> - a character sequence that marks the end of a line of text. <b>Windows</b>: ```CRLF``` (```\r\n```), <b>Linux</b>: ```LF``` (```\n```), <b>macOS</b>: ```LF``` (```\n```, classic <b>macOS</b> used ```CR```).</li>
  <li><b>Monolith</b> - a traditional architecture where all components of an application are built and deployed as a single unit, making it simple to start but harder to scale and maintain as it grows.</li>
  <li><b>Modular Monolith</b> - a monolithic application internally organized into independent modules with clear boundaries, making the codebase easier to maintain while still deployed as a single unit.</li>
  <li><b>Microservices</b> - an architecture where each application component is an independent service with its own database, deployed separately, allowing independent scaling, fault isolation, and flexible technology choices but with higher operational complexity.</li>
  <li><b>Serverless</b> - an architecture where the cloud provider automatically manages infrastructure and scaling, allowing developers to run functions on demand without managing servers, with billing based on actual usage.</li>
  <li><b>Native</b> - traditional architecture where applications run on dedicated servers or containers controlled by the developer, providing full control over the environment but requiring manual scaling and infrastructure management.</li>
  <li><b>Rate limiting</b> - a technique used to control the number of requests a client can make to a service within a specified time window, helping to prevent abuse, ensure fair usage, and protect system stability.</li>
  <li><b>Throttling</b> - a mechanism that regulates the rate of incoming requests by slowing down or delaying excess traffic when limits are exceeded, ensuring system performance and preventing overload.</li>
  <li><b>Vertical scaling</b> - increasing the resources of an existing server, such as CPU, memory, or storage, to handle increased workload.</li>
  <li><b>Horizontal scaling</b> - adding more servers or instances to distribute the workload and handle increased traffic.</li>
  <li><b>DLL (Dynamic Link Library)</b> - a file containing reusable code and data that can be shared by multiple programs.</li>
  <li><b>Applet</b> - a small program designed to run within another application, historically often used to run Java programs inside web browsers.</li>
  <li><b>RAID (Redundant Array of Independent Disks)</b> - a technology that combines multiple physical disks into a single logical storage system to improve performance, provide redundancy, or both.</li>
  <li><b>.env</b> - a configuration file used to store environment variables, which are named values used to configure an application, such as database credentials, API keys, passwords, and application settings. The ```.env``` file mustn't be committed to a public or shared repository because it may contain sensitive information. It is commonly added to ```.gitignore```.</li>
</ul>
